## Executive Verdict

1. **Does a complete path exist today from the game's 2D and 3D draw calls to pixels in the Raylib window?**
   - **YES — structurally wired end-to-end, but currently blocked by two runtime bugs before 2D/3D assets draw** `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/ps2_memory.cpp:740-750, PS2Recomp/ps2xRuntime/src/lib/gs/ps2_gif_arbiter.cpp:25-115, PS2Recomp/ps2xRuntime/src/lib/gs/gs_frontend.cpp:128-311, PS2Recomp/ps2xRuntime/src/lib/gs/gs_cpu_backend.cpp:1335-1457, PS2Recomp/ps2xRuntime/src/lib/ps2_runtime.cpp:3233-3481]`.
   - Specifically:
     - **Path 1 (`VU1 XGKICK`)**: `VU1Interpreter::op_XGKICK` extracts the packet length from the GIF tag at `VU1` data memory `16 * (VI[is] & 0x3FF)` and submits it to `m_gifArbiter->submitPacket(GIF_PATH_1, ...)` `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/vu/ps2_vu1_lower.cpp:695-747]`.
     - **Path 2 (`VIF1 DIRECT` / `DIRECTHL`)**: `PS2Memory::processVIF1Data` forwards raw quadwords to `submitGifPacket(GIF_PATH_2, ...)` `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/ps2_vif1_interpreter.cpp:447-468]`.
     - **Path 3 (`DMA2 GIF` / `GIF_FIFO`)**: `PS2Memory::processPendingTransfers` and `writeIORegister(0x10006000)` submit packets to `submitGifPacket(GIF_PATH_3, ...)` `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/ps2_memory.cpp:740-750, 1218-1231]`.
     - **GS Rasterization & VRAM**: `GS::processGIFPacket` parses `PACKED` (`FLG=0`), `REGLIST` (`FLG=1`), and `IMAGE` (`FLG=2/3`) descriptors, uploads textures into the 4 MB swizzled `m_gsVRAM` via `GS::writeHWREG`, and calls `GSCpuBackend::drawPrimitive` when `XYZ2`/`XYZF2` kick occurs `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/gs/gs_frontend.cpp:128-311, 360-764]`.
     - **Raylib Presentation**: `PS2Runtime::renderFrame` reads `PMODE`, `DISPFB1`/`DISPFB2`, and `DISPLAY1`/`DISPLAY2`, resolves the active page in `m_gsVRAM`, and calls `UpdateTexture(s_frameTexture, m_frameBuffer.data())` + `DrawTexturePro` every tick `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/ps2_runtime.cpp:3233-3481]`.
   - **Current Rendering Status & Previous Black Screen Resolution**:
     1. **Wait loop at `0x284540..0x284558` (`VIF1_MARK` / `INTC_VIF1`) — RESOLVED**: The end-of-frame routine [`sub_00284534_0x284534`](file:///c:/ApeEscape3_Recomp/recomp_source/sub_00284534_0x284534.cpp#L38-L93) waited for `*(int32_t*)0x00649DE4 == 0`, which is incremented by `INTC_VIF1` (`cause = 5`) interrupt handler [`sub_002843D4_0x2843d4`](file:///c:/ApeEscape3_Recomp/recomp_source/sub_002843D4_0x2843d4.cpp#L77-L185) when `VIF1_MARK == 0x2000`. Wired `readIORegister(0x10003C30)` (`vif1_regs.mark`), `writeIORegister(0x10003C30)`, `INTC cause 5` generation on `VIF_MARK 0x2000` / `irq=1`, and handler draining in `sceGsSyncPath`. The wait is completely unblocked `[CONFIRMED logs/step3_rebuild2_err.log:115-327]`.
     2. **Non-Black Pixels Verified**: Frame dumps via `PS2X_DUMP_FRAMES` and `PS2X_DUMP_VRAM` confirm the screen is **NOT black**: `frames/frame_200.png` has **5,099 non-black pixels** showing the Ape Escape 3 monkey with siren and **"Now Loading"** text, and `frames/vram_200.png` has **19,914 non-black pixels** containing full texture sheets `[CONFIRMED logs/step3_rebuild2_err.log:298, 327]`.
     3. **Active Blocker**: The game loops in `sub_003FC100` (`0x3FC190`) waiting for `client->server != 0` because `sid = 0x11223344` is unhandled (`[rpc:bind] UNIMPLEMENTED / refused sid=0x11223344 client=0x0074b240`) `[CONFIRMED logs/step3_rebuild2_err.log:314-363, recomp_source/sub_003FC100_0x3fc100.cpp:108-196]`.
     4. **`CID1` (`file3.irx`) returns dummy status without loading `DATA.BIN`**: The `cid == 1` handler in [`RPC.cpp`](file:///c:/ApeEscape3_Recomp/PS2Recomp/ps2xRuntime/src/lib/Kernel/Syscalls/RPC.cpp#L1201-L1256) writes `'DFCF'` status `0x12`/`0x16` to `0x00771BBC` and invokes `sub_001DCEE0`, but reads **zero bytes** from `DATA.BIN` `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/Kernel/Syscalls/RPC.cpp:1201-1256]`. Consequently, `debug/us/etc/font/seurat_20x20.apefnt` and `seurat_20x20.ttxbin` are never loaded into guest RAM, and the only GS draws in `task-4396.log` are 1 blank texture copy and 2 `rgba=(0,0,0,0)` clear sprites `[CONFIRMED task-4396.log:198-266]`.

2. **Is VU1 supported?**
   - **YES — prominently confirmed** `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/vu/ps2_vu1_core.cpp:1-225, PS2Recomp/ps2xRuntime/src/lib/vu/ps2_vu1_upper.cpp:1-515, PS2Recomp/ps2xRuntime/src/lib/vu/ps2_vu1_lower.cpp:1-799]`.
   - `ps2xRuntime` includes a complete dual-pipeline (64-bit VLIW upper float/SIMD + lower integer/branch/load-store/EFU/XGKICK) **VU1 micro-mode interpreter** (`VU1Interpreter`) with 16 KB micro memory and 16 KB data memory (`0x11008000` / `0x1100C000`), wired to `DMA1` (`VIF1`) -> `processVIF1Data` -> `UNPACK` / `MPG` / `MSCAL` / `MSCNT` / `MSCALF` -> `VU1Interpreter::execute`/`resume` -> `op_XGKICK` -> `GIF_PATH_1` -> `GS::processGIFPacket` `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/ps2_vif1_interpreter.cpp:350-445, PS2Recomp/ps2xRuntime/src/lib/vu/ps2_vu1_lower.cpp:695-747]`.
   - Because VU1 is already implemented and wired to GIF Path 1, **3D rendering is realistic without writing a VU1 emulator from scratch** `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/vu/ps2_vu1_core.cpp:104-224]`.

## Detailed Subsystem Audit

### 1. EE Core (R5900 Instructions, MMI, COP0, COP1, Scratchpad, Address Mapping)

#### 1.1 R5900 Base Integer, 64-bit, and 128-bit Load/Store Coverage
- **Status**: **Implemented (with 2 bugs)** `[CONFIRMED PS2Recomp/ps2xRecomp/src/lib/translator/instruction_translator.cpp:41-598]`.
- **Implemented**:
  - Standard MIPS III/IV 32-bit and 64-bit integer arithmetic, shifts (`DSLL`, `DSLL32`, `DSRA`, `DSRA32`, `DSRL`, `DSRL32`, `DSLLV`, `DSRAV`, `DSRLV`), multiply/divide (`MULT`, `MULTU`, `DIV`, `DIVU`, `MADD`, `MADDU`, `MULT1`, `MULTU1`, `DIV1`, `DIVU1`, `MADD1`, `MADDU1` via `hi1`/`lo1`), `SA` shift-amount register (`MFSA`, `MTSA`, `MTSAB`, `MTSAH`), and 128-bit quadword memory accesses (`LQ`, `SQ` with `& ~0xF` alignment) `[CONFIRMED PS2Recomp/ps2xRecomp/src/lib/translator/instruction_translator.cpp:151-485, PS2Recomp/ps2xRecomp/src/lib/translator/special_translator.cpp:45-312]`.
  - Unaligned load/store instructions (`LDL`, `LDR`, `SDL`, `SDR`, `LWL`, `LWR`, `SWL`, `SWR`) `[CONFIRMED PS2Recomp/ps2xRecomp/src/lib/translator/instruction_translator.cpp:178-315]`.
- **Confirmed Bugs**:
  1. **`BLTZ` / `BGEZ` / `BLEZ` / `BGTZ` (and `L` likely variants) test 32-bit sign instead of 64-bit sign**: In [`control_flow_emitter.cpp`](file:///c:/ApeEscape3_Recomp/PS2Recomp/ps2xRecomp/src/lib/translator/control_flow_emitter.cpp#L421-L444), `REGIMM` branches emit `GPR_S32(ctx, rs) < 0` (or `>= 0`, `<= 0`, `> 0`), whereas `BEQ`/`BNE` right above them (`lines 407-419`) correctly compare `GPR_U64(ctx, rs)`. On R5900, all conditional branches test the full 64-bit register `[CONFIRMED PS2Recomp/ps2xRecomp/src/lib/translator/control_flow_emitter.cpp:407-444]`.
  2. **`MOVZ` / `MOVN` overwrite 128 bits instead of 64 bits**: In [`special_translator.cpp`](file:///c:/ApeEscape3_Recomp/PS2Recomp/ps2xRecomp/src/lib/translator/special_translator.cpp#L123-L126), `OPCODE_MOVZ` and `OPCODE_MOVN` emit `ctx->r[rd] = ctx->r[rs];` (copying the full `__m128i` register) instead of `SET_GPR_S64(ctx, rd, GPR_S64(ctx, rs))`. On R5900, `MOVZ`/`MOVN` only modify bits `0..63` and preserve bits `64..127` `[CONFIRMED PS2Recomp/ps2xRecomp/src/lib/translator/special_translator.cpp:123-126]`.

#### 1.2 R5900 Multimedia Instructions (MMI / MMI0 / MMI1 / MMI2 / MMI3)
- **Status**: **Partial (Implemented, with 2 correctness bugs)** `[CONFIRMED PS2Recomp/ps2xRecomp/src/lib/translator/mmi_translator.cpp:12-498, PS2Recomp/ps2xRuntime/include/ps2_runtime_macros.h:168-824]`.
- **Confirmed Bugs**:
  1. **`HI1` / `LO1` upper-64-bit lane state ignored in MMI multiply/accumulate and move instructions**: `R5900Context` has `hi1` and `lo1` fields (`ps2_runtime.h:133-134`), and scalar `MULT1`/`DIV1`/`MFLO1`/`MFHI1` use them (`special_translator.cpp:138-156`), **but** `MMI_PMFHI`, `MMI_PMFLO`, `MMI_PMTHI`, `MMI_PMTLO`, `MMI_PMFHL_*`, `MMI_PMTHL_LW`, `MMI_PMADDW`, `MMI_PMADDUW`, `MMI_PMADDH`, `MMI_PHMADBH`, `MMI_PMSUBW`, `MMI_PMSUBH`, `MMI_PHMSBH`, `MMI_PMULTW`, `MMI_PMULTUW`, `MMI_PMULTH`, `MMI_PDIVW`, `MMI_PDIVUW`, and `MMI_PDIVBW` in [`ps2_runtime_macros.h`](file:///c:/ApeEscape3_Recomp/PS2Recomp/ps2xRuntime/include/ps2_runtime_macros.h#L168-L824) only read/write `ctx->hi` and `ctx->lo` (returning `0` or discarding results for the upper 64-bit lanes that belong in `ctx->hi1`/`ctx->lo1`) `[CONFIRMED PS2Recomp/ps2xRuntime/include/ps2_runtime_macros.h:168-334, 496-508, 636-646, 650-687]`.
  2. **`MMI_PADDUH` and `MMI_PSUBUH` do not saturate**: In [`ps2_runtime_macros.h`](file:///c:/ApeEscape3_Recomp/PS2Recomp/ps2xRuntime/include/ps2_runtime_macros.h#L477-L483), `MMI_PADDUH` calls `_mm_add_epi16` instead of `_mm_adds_epu16`, and `MMI_PSUBUH` calls `_mm_sub_epi16` instead of `_mm_subs_epu16` `[CONFIRMED PS2Recomp/ps2xRuntime/include/ps2_runtime_macros.h:477-483]`.

#### 1.3 COP0 & COP1 (FPU)
- **Status**: **Partial** `[CONFIRMED PS2Recomp/ps2xRecomp/src/lib/translator/cop_translator.cpp:15-410, PS2Recomp/ps2xRuntime/include/ps2_runtime_macros.h:851-976]`.

### 2. Kernel, Threads, Semaphores, Event Flags, Alarms, Interrupts & Scheduler

#### 2.1 Cooperative Thread Scheduler & Busy-Wait Yielding
- **Status**: **Implemented** `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/EeScheduler.cpp:477-995]`.
- **Design**:
  - Single-host-thread cooperative scheduler (`EeScheduler::runTick`, `quantum = 8000` calls/branches per tick) `[CONFIRMED PS2Recomp/ps2xRuntime/src/lib/ps2_runtime.cpp:3552, PS2Recomp/ps2xRuntime/src/lib/EeScheduler.cpp:740-965]`.

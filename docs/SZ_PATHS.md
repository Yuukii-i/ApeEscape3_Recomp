# Detailed Analysis: EE `.sz` Path Construction & Asset Loading

## 1. Executive Summary & Core Findings

This investigation determines why the EE requests `debug/us/static/exdb_sound.pck` without the `.sz` extension while requesting `debug/us/startup/exdb_common.pck.sz` with `.sz`.

- **Finding 1 (String Tables in SCUS_975.01)**: The premise that *no `.sz` string exists in SCUS_975.01* is **factually incorrect**. The executable contains exactly **34 occurrences of `.sz`** embedded in `.rodata`, including the full literal `"/startup/exdb_common.pck.sz"` in two distinct locations (`0x006EA798` and `0x006D07F8`), as well as standalone extension strings `".sz"` (`0x006EB210`, `0x006F10F8`) and `".bin.sz"` (`0x006EE630`) `[CONFIRMED SCUS_975.01:0x5D17F8, 0x5EB798, 0x5EC210]`.
- **Finding 2 (Path Construction)**: Neither path is dynamically formed with a runtime `.sz` concatenation flag. Both paths originate as compile-time string literals (`"/static/exdb_sound.pck"` and `"/startup/exdb_common.pck.sz"`). The prefix `debug/us/` is prepended by `sub_0025035C` using the formatted root string buffer at `0x006493C8` (generated by `sub_00252AE4` using format string `debug/%s/`) `[CONFIRMED recomp_source/sub_0025035C_0x25035c.cpp:15-30, recomp_source/sub_00252AE4_0x252ae4.cpp:20-40]`.
- **Finding 3 (Disc Layout Discrepancy)**: In `DATA.BIN` on the game disc (`ApeEscape3.iso:LSN_3576`), **100% of files in `debug/us/static/` and `debug/us/startup/` are stored with `.sz` compression**. In contrast, sound bank sample files in `debug/us/sound/se/` (`*.hd`, `*.bd`) and streaming files in `debug/us/sound/stream/` (`*.x`) are stored **uncompressed (plain)** `[CONFIRMED ApeEscape3.iso:LSN_3576 VFI index table]`.
- **Finding 4 (Division of Responsibilities & Conclusion)**: The game really and genuinely requests the plain name `debug/us/static/exdb_sound.pck`. Because the sound parser `sub_0026D228` has no decompression routine and requires uncompressed PCK header data, and because the EE asset loader `sub_0024FA04` strictly skips software zlib decompression when the requested path does not end with `".sz"`, the low-level IOP/VFI layer must transparently map and decompress `exdb_sound.pck` when serving the EE. **Conclusion: Option (a) is confirmed**. The transparent fallback and decompression in `VfiArchive` is faithful to the required runtime contract.

## 4. Evaluation of Variables, Flags, Region, & Boot Mode (Question 3)

### 4.1 Is `.sz` Chosen by a Flag or Runtime Variable?
**No.**
1. **Direct String Literal Call Sites**:
   - `sub_0035FB44` line 485:
     ```cpp
     SET_GPR_S32(ctx, 5, (int32_t)((uint32_t)113 << 16));
     SET_GPR_S32(ctx, 5, (int32_t)ADD32(GPR_U32(ctx, 5), 16520)); // 0x00714088
     // ctx->pc = 0x252B3C (func_252B3C)
     ```
     This passes immediate address `0x00714088` (`"/static/exdb_sound.pck"`) directly into register `$a1`.
   - `sub_00246738` line 456:
     ```cpp
     SET_GPR_S32(ctx, 5, (int32_t)((uint32_t)111 << 16));
     SET_GPR_S32(ctx, 5, (int32_t)ADD32(GPR_U32(ctx, 5), -22632)); // 0x006EA798
     // ctx->pc = 0x252B3C (func_252B3C)
     ```
     This passes immediate address `0x006EA798` (`"/startup/exdb_common.pck.sz"`) directly into register `$a1`.
   - Neither call site executes any conditional branch or register calculation based on a flag, boot-mode, disc-type, or build configuration.
2. **Dynamic Path Generator (`sub_0025182C`)**:
   - For all other startup and static XML/PCK files (`damageconfig.xml`, `ui_static.pck`), the path is assembled in `sub_0025182C` by concatenating:
     `dir + "/" + name + "." + ext`
   - The extension passed to `sub_0025182C` is always the bare extension (`"xml"`, `"pck"`, `"bin"`). It never appends `.sz`.
3. **Region Determination (`sub_00252AE4`)**:
   - The only runtime parameter evaluated is the 2-letter language/region identifier passed to `sub_00252AE4`.
   - `sub_00252AE4` formats `"debug/%s/"` (`0x006EB358`) into the global buffer at `0x006493C8` using `ps2_stubs::sprintf`.
   - This sets `debug/us/` (or `debug/jp/`), but has zero effect on file suffixes or `.sz` presence.

## 5. Architectural Conclusion (Question 4)

### 5.1 Evaluation of Hypotheses

- **Hypothesis (b) Disproven**: A variable is NOT wrong due to a recompiler deviation.
  - The MIPS machine instructions in `SCUS_975.01` and the translated C++ in `recomp_source` both load the exact 32-bit pointer `0x00714088` for `exdb_sound.pck` and `0x006EA798` for `exdb_common.pck.sz`.
  - The translator output matches the original game binary 1:1 with zero divergence.
- **Hypothesis (a) Confirmed**: The game **really and intentionally** requests `debug/us/static/exdb_sound.pck` plain.
  - The sound team authored `sound::Task` to request `"/static/exdb_sound.pck"`.
  - The sound parser `sub_0026D228:250-448` is an in-memory parser for the raw `PCK\0` archive header. It has no zlib decompression code.
  - If served compressed `.sz` bytes, `sub_0026D228` reads offset `0x08` (the DEFLATE stream payload) as the archive file count, triggering an infinite loop of 513 million iterations at PC `0x0026D29C`.
  - The EE general loader `sub_0024FA04:1277-1300` checks `task->path.rfind(".sz") == len - 3`. If the requested path does not end with `".sz"`, it bypasses the software inflate routine.
  - Consequently, if the archive layer does not resolve `exdb_sound.pck` to `exdb_sound.pck.sz` and decompress it prior to delivery, the sound engine cannot initialize.

### 5.2 Why the VFI Transparent Workaround is Faithful
On original PS2 hardware running from `DATA.BIN`, the IOP `file3.irx` / VFI filesystem driver handled sector mapping from the CD/DVD. In `ApeEscape3_Recomp`:
1. When a file is requested with `.sz` (`exdb_common.pck.sz`):
   - `VfiArchive` serves the raw compressed bytes from `DATA.BIN`.
   - `sub_0024FA04` on the EE identifies the `.sz` extension and runs its native software decompressor (`inflateInit2_(&strm, -15, "1.2.1", 72)`).
2. When a file is requested without `.sz` (`exdb_sound.pck`):
   - On disc, only `exdb_sound.pck.sz` exists.
   - `VfiArchive` detects that the plain name was requested, parses the 4-byte uncompressed size header (`468,240` bytes), inflates the RFC 1951 raw DEFLATE stream via `puff`, and delivers uncompressed bytes to the EE buffer.
   - `sub_0024FA04` bypasses its decompressor and hands the uncompressed buffer to `sub_0026D228`.
   - `sub_0026D228` successfully parses the PCK header and registers all audio stream descriptors.

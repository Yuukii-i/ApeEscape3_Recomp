# Task M10: VU float semantics in clipPolygon - saturate to +-FLT_MAX instead of producing Inf/NaN (fix for the spike polygons)
Budget: "[call N/12]", stop at 12. Edit ONLY PS2Recomp/ps2xRuntime/src/lib/vu/vu1_func.inc (no headers). DO NOT BUILD/RUN/COMMIT. Mark `// FIX-M10`.
Root cause (logs/m9b1_err.txt, PROBE-M9): the game feeds the VU1 clip handler (0x2900, `clipPolygon`) polygons whose clip-space vertices are ~1e37..2.8e38 (near FLT_MAX; on real PS2 a division by zero yields +-FLT_MAX, e.g. normalising a zero vector, so these exist in PCSX2 too and are harmless there). Example: in[0]=(-1.2e37,3.0e37,-1.17e38,-1.168e38), in[1]=(-1.9e38,2.0e38,2.8e38,2.8e38), in[2]=(8.3e37,-1.0e38,-2.4e37,-2.4e37); plane -Z sides=101, t=[0,0]; +Z sides=010 t=[0,0.99999]; output = 4 vertices that are ALL (0,0,0,0) with fog=255 => visible giant triangle (spike) next to real vertices. Cause: our interpolation does IEEE float arithmetic on near-FLT_MAX operands: (v1 - v0) overflows to +-Inf and t*(Inf) = NaN when t == 0 (0*Inf), or a-b overflow makes t NaN, and NaN later becomes 0. Real VU/EE math never yields Inf/NaN: every FMAC result is clamped to +-FLT_MAX (sign kept), 0*FLT_MAX = 0, and flags are set instead. Fix in the engine only for the arithmetic used by clipPolygon (and its helpers: plane distance tests, t = a/(a-b), the lerp of pos/tex/col/fog), without changing results for normal-magnitude inputs.

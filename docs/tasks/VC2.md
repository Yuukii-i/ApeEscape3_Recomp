# Task VC2 (part B): host tool that runs the same COP2 test through OUR recompiler's emitted code and diffs against PCSX2
Budget: "[call N/12]", stop at 12. Create/edit ONLY files under tools/vucheck/ (+ a tools/vucheck/build.bat). DO NOT touch runtime/recompiler sources. You MAY build the tool with MSVC (see tools/fpucheck.bat for env/flags; add /I for fmt/toml includes found under PS2Recomp/ or third_party). DO NOT commit.
Inputs (made by VC1): tools/vucheck/ops.txt (`name hexword`, 294 lines), inputs.bin/inputs.txt (32 cases; read tools/vucheck/gen_pcsx2_test.py + layout.txt for the exact binary layout), PCSX2 results will appear as tools/vucheck/pcsx2_results.bin = 294*32 records of 64 bytes (op-major, case-minor): vf3[16] vf5(acc)[16] status mac clip Q I pad pad pad (u32 each). Per case the guest did: vf1,vf2,vf6,vf7 loaded; ACC := vf6*vf7 (VMULA.xyzw); I,Q set from the case; status/mac/clip cleared; vf3 preset to sentinel 0xDEADBEEF lanes; then ONE op; then flags/Q/I/vf3 read, ACC read back with vmaddx.xyzw vf5,vf0,vf0x (adds ACC+vf0*0).
Goal: for every (op,case) compute the same record using the code OUR RECOMPILER EMITS for that instruction word, and print a diff. Best method (exact): link the recompiler's decoder + VU/COP2 translator (PS2Recomp/ps2xRecomp/src/lib: r5900_decoder.cpp, vu_translator.cpp, vu_translation_helpers.cpp, code_generator.cpp or whatever is minimal; headers under PS2Recomp/ps2xRecomp/include) into a generator exe `vucheck_gen.exe` that, for each word in ops.txt, decodes it and prints the emitted C++ statement(s); write them into a generated `vucheck_ops.inc` (one `static void op_N(R5900Context* ctx)` per op using the same `ctx->vu0_vf[..]`, `ctx->vu0_acc`, `ctx->vu0_q`, `ctx->vu0_i`, status/mac/clip members the emitted code uses). Then `vucheck.cpp` includes PS2Recomp/ps2xRuntime/include/ps2_runtime_macros.h + ps2_runtime.h (stub any undefined externs like fpucheck.cpp does) and the generated file, replicates the guest sequence (including the ACC seeding by VMULA via the emitted code for that opcode word 0x4A?? for VMULA.xyzw vf6,vf7 -- generate that via the same generator, and the final vmaddx readback), applies MXCSR exactly like the game thread (round-toward-zero unless --rn; see tools/fpucheck.cpp), and compares with pcsx2_results.bin. If linking the recompiler is impractical (say why in 1 line), fallback: copy the per-op emit format strings from vu_translation_helpers.cpp verbatim into hand-written functions with a comment naming each source line.
Flags: how our code exposes status/mac/clip (VI 16/17/18) -- find the ctx members used by the emitted CFC2/ops (grep vu0_status, vu0_mac, vu0_clip or similar in vu_translation_helpers.cpp / ps2_runtime.h); if our emitted code does NOT maintain MAC/status/clip for an op at all, still run and report `FLAGS-NOT-MODELLED` for that op.
Output: per op: `op <name>: vf3 mismatches <n>/32 acc <n>/32 status <n>/32 mac <n>/32 clip <n>/32 Q <n>/32`, classification KNOWN (denormal input, exp255 input, NaN-ish, max-clamp 0x7fffffff vs 0x7f7fffff) vs REAL, and the first 4 REAL mismatches per op with a,b,pcsx2,ours (hex). Final summary table of ops with REAL>0 sorted by count. Until pcsx2_results.bin exists, support `--selftest` that just runs all ops without comparing and reports crashes.
Acceptance: tools/vucheck/build.bat builds vucheck.exe (and vucheck_gen.exe if used) and `vucheck.exe --selftest` runs all 294 ops with no crash. Reply <=6 lines (method used, counts, anything not modelled).

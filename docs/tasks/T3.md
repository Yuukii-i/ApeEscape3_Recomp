# Task T3: make a SYNCHRONOUS sceSifCallRpc block the calling guest thread until the modelled IOP completion time (env PS2X_RPC_BLOCK=1, default OFF)
Budget: "[call N/12]", stop at 12. Edit ONLY .cpp files under PS2Recomp/ps2xRuntime/src/lib/Kernel/ (RPC.cpp, EeScheduler.cpp). No headers (if you need a new declaration, use a local `extern` in the .cpp that uses it, as the files already do). Mark `// FIX-T3`. DO NOT BUILD/RUN/COMMIT.
PCSX2 truth (docs/RELEASE1_PLAN.md, slot 2 + breakpoints): the SDK function sceSifCallRpc is guest code at 0x439b40..0x439bf8: it CreateSema()s a temp semaphore, sends the call with SifSendCmd (cmd 0x8000000a), then WaitSema()s (WaitSema(10) from ra=0x439bec) until the IOP replies (an interrupt handler iSignalSema()s it from 0x439448). So a sync RPC (mode without the NOWAIT bit) blocks the main thread (guest tid 1) for the whole IOP service time. During the stage load the real game's main thread is therefore blocked for ~2.8 s: it submits zero draws and the screen holds the last frame (white fade). Our HLE (RPC.cpp `SifCallRpc` L1570+, `sceSifCallRpc` L2311) replaces the guest function and returns immediately (`signalRpcCompletionSema` is called at once), so the main loop keeps ticking: PROBE-T2 trace shows tid1 never calls WaitSema in the load window, [t1-pub] shows the fade-out starting while the stage files are still being read (reads span ~1100 log lines after the fade peak).
Existing pieces: FEAT-E8c Cid1DriveModel gives each CID1 read a modelled cost ([dvd] op=.. cost=..ms due=+N vbl) and defers replies via a pending queue delivered at vblank (FIX-AU5, EeScheduler processDueDeadlines). Use that same due time.
Do (only when env PS2X_RPC_BLOCK=1; default off = unchanged):
1. In SifCallRpc, for a call with `(mode & kSifRpcModeNowait) == 0` that is dispatched to the IOP/CID1 path and has a modelled due time > now, do NOT return to the guest yet: block the calling guest thread (use the scheduler's own blocking primitive the WaitSema implementation uses, e.g. a per-call temp semaphore + a deadline that signals it at the due vblank/time, or the existing pending-queue completion) and resume it exactly when the modelled reply would be delivered. The recv buffer/result must be visible to the guest only after it resumes (do not change what data is written, only when the guest regains control).
2. Calls with NOWAIT, or with no modelled cost (due now), behave exactly as before. Never block the scheduler/vblank/IOP threads or any thread that is not a guest thread; never block while holding g_sif_call_rpc_mutex or g_rpc_mutex (release locks first). Guard against deadlock: cap one block at 10 s of guest time and log `[rpcblock] timeout`.
3. Log (PS2X_RPC_BLOCK=1 only): `[rpcblock] tid=%d sid=0x%08x fno=0x%x mode=0x%x dueVbl=+%d blockedMs=%.1f` when a call resumes.

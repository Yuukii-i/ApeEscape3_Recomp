# Task IP1: IPU activity probe (probe only, env PS2X_IPU_LOG=1) - what does the game send to the IPU when the level-select preview appears?
Budget: "[call N/12]", stop at 12. Edit ONLY .cpp files under PS2Recomp/ps2xRuntime/src/lib/ (Kernel/Stubs/IPU.cpp, Kernel/Stubs/MPEG.cpp, Kernel/Stubs/DMA.cpp, ps2_memory.cpp, Kernel/Syscalls/*.cpp as needed). No headers. DO NOT BUILD/RUN/COMMIT. Mark `// PROBE-IP1`. Static bool read once; unset = one bool test.
Why: the level-select TV preview is drawn by the game from two 256x256 PSMCT32 textures (tbp 0x2e40, 0x3240) + a 256x128 PSMT8 layer (tbp 0x3640) (PCSX2 dump refs/pcsx2_dumps/ref_levelselect). Those 32-bit textures should be produced by the PS2 image processor (IPU) decoding a compressed picture. Ours shows the TV blank. docs/CAPABILITY_AUDIT.md section 7.1: IPU is only partially emulated (sceIpuSync/sceIpuIsBusy return 0, IPU_CTRL 0x10002010 reads idle at ps2_memory.cpp ~L2268, CH3 fromIPU / CH4 toIPU DMA 0x1000B000 / 0x1000B400 handled by DMA.cpp/IPU.cpp).
Do (only when PS2X_IPU_LOG=1), rate-limit 600 lines per run, every line carries a monotonically increasing host counter `seq=` and `ra=0x%08x` (guest return address where available):
1. Log every guest call into the sce IPU / MPEG library HLE functions (all functions in IPU.cpp and the MPEG.cpp sceMpeg*/sceIpu* entry points): name + args (a0..a3 + any stack args that matter) + result: `[ipu] fn=sceIpuXxx a0=.. a1=.. a2=.. a3=.. ret=..`.
2. Log raw MMIO: writes to IPU_CMD 0x10002000 (decode the command nibble: BCLR=0, IDEC=2, BDEC=3, VDEC=4, FDEC=5, SETIQ=6, SETVQ=7, CSC=8, PACK=9, SETTH=10; and its option bits for IDEC/CSC: OFM output format, DTE dither, SGN, DTD, QSC, FB), writes to IPU_CTRL 0x10002010, reads of IPU_CMD/CTRL/TOP (0x10002030) with the value returned, and accesses to IPU_in_FIFO 0x10007010 / IPU_out_FIFO 0x10007000 (count + first qword only).
3. Log DMA ch3 (fromIPU, 0x1000B000) and ch4 (toIPU, 0x1000B400) starts: `[ipu-dma] ch=%d madr=0x%08x qwc=%u chcr=0x%08x tadr=0x%08x` and, for ch4 (data going INTO the IPU), the first 32 bytes of the source (hex) and whether the data starts with an MPEG start code (00 00 01 xx), plus the number of qwords; for ch3 (data coming OUT of the IPU), the destination and size, and what our HLE actually writes there (first 16 bytes, all-zero or not).
4. Every 2 s print `[ipu-sum] calls=%u cmds=%u dma3=%u dma4=%u zeroOut=%u` and the distinct (cmd,ofm) pairs seen.
5. No behaviour change.
Accept: compiles; reply <=4 lines with file/line ranges.
